# BioOpt 科学计算优化

目标是在保留生物学任务和验收标准的前提下，用可复查的实验找到性能最好的可行方案。

## 六步流程

1. **查清任务。** 查 GitHub 的正式仓库、版本和 issue，读论文、作者教程及相关社区经验，再查本地命令、日志与产物。核对当前代码的入口、输入、输出和期望应用场景。遇到来源冲突，追到对应版本和实际执行路径，记录采信依据。
2. **确认复现基线。** 查作者是否提供可执行的小试、教程、参考输出或复现手册。找到后，先核对原运行记录是否能证明同版本、同任务跑通，证据不足就实际运行。作者未提供可用基线，或复现失败时，提示具体缺项，列出可核实的替代证据。可信基线成立后再进入正式配对。
3. **确定生物学任务与指标。** 根据论文、教程和复现结果写清算法回答的生物学问题、核心输出与允许的变化。先冻结科学正确性指标和通过规则，再定用于排序的性能指标、测试范围与资源预算。根据任务与基线实测波动决定如何验证稳定性。
4. **从复现轨迹提出候选。** 分阶段读计时、内存、设备占用和数据搬运，定位主瓶颈。沿下表每条路线提出至少 **3 个机制不同**的候选。每个候选写清证据、改动、预期收益、风险及最小证伪实验。记录受当前瓶颈、硬件或工作量约束的候选。
5. **由独立评估 Agent 排序。** 评估 Agent 查看同一份基线、指标和候选表，按任务正确性风险、预期性能收益、证据强度、实现成本和验证成本排序。输出逐项理由、建议先跑的实验及淘汰条件。环境支持时使用独立子代理，执行侧据此安排优先级。无法委派时，先完成单独的评估记录再动实现。
6. **并行小试，交叉确认最优方案。** 资源和工具允许时，用独立子代理或多进程推进不同候选，隔离实现、输出和评测资源。每轮先验科学指标，再测性能，保留收益不足或未通过的证据。复测领先方案，交叉比较单项和可组合的改动，检查效果能否叠加。最终在统一的代表性工作负载下配对复核，选出满足正确性和资源约束的已测最优方案，交付改动、复现命令、原始测量、取舍和适用范围。[配对工具说明](references/benchmark.md)

## 优化路线

| 路线 | 从这些切入点形成不同候选 |
|---|---|
| CPU 多进程 | 独立任务分片、粗粒度任务批处理、worker 共享只读状态。检查序列化、线程过量和调度成本。 |
| CPU 迁移到 GPU | 迁移主热点算子、批量或融合小算子、让中间量驻留设备。计入传输、同步、初始化和精度影响。 |
| 大内存计算与合并 | 合并共享上下文的计算以复用初始化、分块或流式处理、复用中间缓冲或减少内存副本。共同测量峰值内存和端到端时间。 |
| 单卡优先与多卡扩展 | 先尝试降低峰值使任务放入单卡、在单卡合并独立工作、优化单卡的数据与算子调度。单卡在目标工作量下仍无法满足显存或时限时，再比较多卡分片、通信和合并成本。 |
