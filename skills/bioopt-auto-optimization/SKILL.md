# BioOpt 科学计算优化

目标是在保留生物学任务和验收标准的前提下，用可复查的实验找到性能最好的可行方案。

工作流内置本地 Codex 的 Scout、Baseline、Optimize 和 Experiment 的执行规则，并用 Skill Creator 组织入口和参考文件。运行时直接使用本包的[工作流底座](references/workflow-base.md)。其中记录了每步的产物和放行条件。

## 六步流程

1. **查清任务（Scout）。** 从用户任务和可核查的本地命令、日志、产物恢复现状。查 GitHub 正式仓库、版本和 issue、论文、作者教程与社区经验，优先核对会改变复现路线的疑点，也查可能推翻当前理解的证据。交付实际入口、任务范围、待确认项和可能的基线路线。
2. **确认复现基线（Baseline）。** 先区分本轮需要“可信对照”还是“忠实复现作者结果”。核对作者有无可执行的小试、教程或参考结果。按最小可信成本选择复用已验收记录、导入有出处的结果或实际复现。让每个验收主张能追到版本、输入、命令和真实产物。缺作者基线时明确提示，现有替代证据按自身口径登记。基线无法支撑比较时，给出阻塞和缺失证据。
3. **确定生物学任务与指标（Baseline → Experiment）。** 用论文、教程和复现数据确认核心任务。冻结评估入口、比较数据、必需指标、优劣方向、通过阈值、资源预算和测量范围。正确性是放行条件，性能指标用于排序。基线稳定性验证由任务和实测波动决定。
4. **从复现轨迹提出候选（Optimize）。** 先查同一瓶颈已有尝试，再剖析实际入口的阶段耗时、内存、占用和数据搬运。沿下表每条路线写至少 **3 个机制不同**的候选。每个候选记录瓶颈证据、假设、最小改动、预期收益、风险、能推翻假设的小试和晋级条件。候选先登记进同一张表，排序后再分配实施资源。
5. **由独立评估 Agent 排序（Optimize）。** 评估者使用同一基线、验收合同和预算，对证据强度、语义风险、预期收益、资源与验证成本逐项给理由。只把排名靠前且有明确证伪条件的候选推进到实施。注明待验证、暂缓和淘汰理由。无法调用独立子代理时，先单独完成评估记录再实施。
6. **并行小试与交叉确认（Experiment → Optimize）。** 资源和工具允许时，用独立子代理或多进程推进不同候选，隔离代码、输出和测量资源。运行前写明改动、命令、条件及收据位置。小试过正确性门槛后再测性能，只有通过正式配对的结果进入最终排序。对领先候选做同条件交叉复测，组合收益须单独验证。每批结束更新当前最佳方案，并有依据地选择继续探索、集中验证、融合、修复或停止。交付最优已测方案、复现命令、原始数据、失败尝试和适用范围。[配对工具说明](references/benchmark.md)

## 优化路线

| 路线 | 从这些切入点形成不同候选 |
|---|---|
| CPU 多进程 | 独立任务分片、粗粒度任务批处理、worker 共享只读状态。检查序列化、线程过量和调度成本。 |
| CPU 迁移到 GPU | 迁移主热点算子、批量或融合小算子、让中间量驻留设备。计入传输、同步、初始化和精度影响。 |
| 大内存计算与合并 | 合并共享上下文的计算以复用初始化、分块或流式处理、复用中间缓冲或减少内存副本。共同测量峰值内存和端到端时间。 |
| 单卡优先与多卡扩展 | 先尝试降低峰值使任务放入单卡、在单卡合并独立工作、优化单卡的数据与算子调度。单卡在目标工作量下仍无法满足显存或时限时，再比较多卡分片、通信和合并成本。 |
