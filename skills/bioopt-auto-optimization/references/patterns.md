# 根据剖析选择优化

| 实测现象 | 首选变更 | 必查失败方式 |
|---|---|---|
| Dense 相似度绝大多数值未使用 | 先构建等价候选，再只计算实际使用的值 | 候选若依赖全量分数，提前筛选会改变算法。保留原 k、近邻与过滤的顺序、空集合和并列行为。 |
| 每目标重复构建耗时对象 | 多目标共用初始化，或按完整依赖键缓存 | 用单目标、混批、置换和重复项验证，混批可能影响统计量。计入缓存构建与命中。 |
| 多目标共用源切片或不可变状态 | 复用目标无关的传输计划、行索引或查询常量 | 检查端点顺序、实际参数、内部状态与随机 anchor，核实入口是否已复用。 |
| 跨进程反复 pickle 大矩阵 | 只改搬运方式，复用原数值函数 | 检查只读共享、生命周期、计算结果和峰值内存。只报告实测完成范围。 |
| 大量微小数值调用 | 合并调用、向量化或编译 | 检查舍入、快速数学、异常输入和 RNG。批量运算保持逐实体合同。 |
| 写出前积累大块数组 | 按消费者的有效粒度流式写出，释放中间量 | 校验顺序、掩膜、空值和落盘完整性。临时文件验收后原子发布。 |
| CPU/GPU 或流水线闲置 | 对已证明独立的单元分片 | 计入初始化、搬运、同步、合并与等待。更多资源的效果单列。 |
| 可恢复步骤重复或错误命中 | 绑定源码、有效配置、完整输入和外部参考的内容指纹 | 测同路径等长改写、输出损坏与依赖变化，保留验证成本。 |

组合前保留单项证据，组合后重新验收。冷启动主导时分别报首次和稳态。候选持平、变慢或不等价时记录条件，并按瓶颈决定下一步。

剖析优先记录分阶段 wall time、RSS 与设备内存。Python 可按环境用 cProfile、py-spy 或 Scalene，CUDA 可用框架 profiler 或 Nsight。编译、自动调参和候选生成均由科学验收约束，再按实测性能筛选。
