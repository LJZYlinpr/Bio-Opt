# 专家优化轨迹库

## SpatialZ · 人工设计的优化轨迹

**任务与基线。** 根据已测切片的空间坐标与表达，生成目标深度中的细胞位置、细胞类型与基因表达。作者小试使用 MERFISH；生产目标是把同一生成流程扩到 ABCA-1 全序列。先用小试和固定中间量隔离每项改动，再用生成入口验证组合实现。[作者原版、优化代码和验收收据](https://github.com/LJZYlinpr/Bio-Opt/tree/main/algorithms/SpatialZ)

### 1. 沿数据流找到浪费

读作者表达合成入口，从候选权重往回追。程序先构造每个参考细胞与每个生成细胞的全量余弦矩阵，再从矩阵中取实际供体的分数。XY 树的近邻请求数上限为 50，因此大部分相似度不会参与抽样。将“哪些值被读取”变成优化的第一条证据。

### 2. 把候选规则写成对照

作者先用同类型参考细胞数限制近邻请求数，再在**全体参考细胞的 XY 树**中查询，最后筛掉不同类型。直接按类型建树会让一些原本无候选的生成细胞从更远的位置得到供体。这个反例否决了重写候选集的做法。保留全局树、每类请求数、供体顺序和空候选处理，仅在确定供体后计算余弦。

### 3. 拆开数学工作与执行开销

**候选余弦。** 一次规范化参考和查询描述符，沿已选供体计算实际要读取的相似度。按原权重参数构造概率和累积分布，保留索引顺序。

**编译采样。** 原版对每个基因调用一次抽样。候选按原查询与基因顺序用 MT19937 预生成随机数，再用 C++ 遍历累计概率以选择供体，使用 OpenMP 按生成细胞并行。基因从选中的供体取原值。空候选行维持原行为，随机数分配也遵循原抽样顺序。

### 4. 逐级验证并扩大计时边界

### 5. 在全量任务上换执行结构

- **GPU 几何 → CPU 表达。** 沿作者目标和迭代计算 XY，层就绪后交给 CPU 处理标签、MENDER 和表达。CPU 可写出前一层时 GPU 仍在求下一层。逐层提交和恢复，使一次失败只需重做未完成层。
- **按相邻实测深度排队。** 143 个相邻深度对经共享队列分发。稳定任务 ID 和按层种子避免调度顺序改变抽样。队列保留领取、限流与重试记录。
- **逐层落盘。** 保存几何和稀疏表达，释放描述符、内存缓冲及设备缓存。三层流式试验核对了稀疏表达数据及索引、XY、标签和基因轴，确认首层表达写出早于下一层几何完成。560 µm 层 CPU RSS 从释放前 916.75 MiB 到释放后 769.55 MiB，GPU 该层峰值 330.92 MiB、结束已分配 16.25 MiB。这些是单次运行内的内存观测。

### 6. 追到 Fig. 3 实际采用的版本

全量 ABCA-1 使用上述手工实现，产物有 22,574,061 个点和 1,133 个深度，其中 144 个实测深度、989 个生成深度。Fig. 3 的三个五切片窗口沿用作者表达合成，并将 MENDER worker 从 200 调为 4。全量生产实现逐层运行 MENDER，后续的合批实验收录在 Agent 库。全量工作量和调度能力有产物收据，速度比较采用上表各自的配对范围。
